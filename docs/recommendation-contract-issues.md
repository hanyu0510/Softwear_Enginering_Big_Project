# 推荐模块接口契约待确认事项

正式依据为 `Big_Project/dev-alignment-doc(1).md`；`衣搭接口设计草案.docx` 只供参考。本实现不修改其他组员接口或数据库。

| 问题 | 冲突或空缺 | 暂行实现 | 建议团队决议 |
| --- | --- | --- | --- |
| 日期语义 | 5.5 允许本地传 `date`，3.12 写本地当日；`date` 和 `travelDate` 可同时存在 | 本地仅当日；旅行两日期并存须相同，否则 `40001`；超预报范围生成时降级，独立天气接口 `50301` | 明确是否支持本地未来日期及两日期优先级 |
| 天气错误与降级 | 4.2 写 `50301` 错误，5.5 写主推荐不中断 | 独立 `/weather` 返回 HTTP 503/code 50301；推荐成功时 HTTP 201/code 0，`weather=null` 且 `warnings` 提示 | 确认成功降级的状态码和前端显示规则 |
| 模型状态 | 示例只有 `generated`，未定义完整枚举 | `generated`/`rule_based`，解析回退以 warning 表示 | 统一枚举和分阶段状态 |
| 历史分页 | 4 节只要求 `total`，5.5 未给内部列表字段；草案用 `items` | 暂用 `{list,total,page,pageSize}`；只返回当前用户 | 与前端确定 `list` 还是 `items` |
| 历史失效 | 3.4 要求保留快照或标记不可用，详情没有字段定义 | 历史详情单品加 `available` 布尔值，快照保留 | 确认是否纳入正式 ItemSnapshot Schema |
| 城市位置 | 用户当前城市来源未确定 | `WardrobePort.current_city_id` 可注入；未取得则无天气降级 | 账号/前端确定用户当前城市获取方式 |
| 色卡 | 2.5 要求共享白名单，但未列完整清单 | `contracts.COLORS` 为推荐模块暂行语义色集合 | 衣橱与推荐负责人共同确定共享色卡 |
| 物理模型 | PDM、数据库类型及数组存法未定 | 推荐自有 SQLite 表用于独立联调；跨模块只用 `WardrobePort` | 数据库负责人定稿后迁移并替换适配器 |
| 认证 | 仓库原型固定单用户、无 Token | 仅 mock 模式接收两枚显式模拟 token；live 模式拒绝直至注入账号适配器 | 账号负责人提供 token 验证服务/接口 |
| 草案冲突 | 草案的 `/locations`、`lockedItems`、字符串错误码和旅行多日接口与正式契约不符 | 使用 `/cities`、`locked_items`、数字错误码；不做多日旅行 | 归档草案旧字段，避免前端混用 |
| 商品样本 | `Big_Project/garment` 是公开零售商品，不是用户自有衣橱或团队心愿衣橱 | 仅映射给虚拟测试用户，清楚标注“模拟拥有”；正式库不写入 | 后续用真实用户上传且已确认的数据替换 |

第三方天气结构中的 `observedAt` 目前记录**取得预报的时间**，而不是现场观测时间；`forecast=true`。建议把字段语义正式写入契约。心愿源单品是否公开可用由衣橱服务在候选读取和保存前再次判断。
